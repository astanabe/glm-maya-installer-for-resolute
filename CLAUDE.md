## Project status

`install-glm-maya.sh` is implemented (2026-11-17) but **has never been run on real hardware** (the development machine has no supported GPU). Everything after the prompts (apt, the service user, Maya's real setup, systemd, ufw, the final tests against a real Maya, `--uninstall`) is untested; what was checked on the development machine is listed in README "Verification". `README.md` is the source of truth for behavior, options, defaults, file layout and procedure. Keep it in sync when the implementation changes, including its "Verification" section and the "Status" note at its top.

Everything the specification says about Project Maya comes from reading the documentation and source of Maya v1.1.63 (https://github.com/mw00/project-maya/releases/tag/v1.1.63), not from running it: the development machine has no supported GPU. There is no copy of Maya on the development machine; download the tag archive into a scratch directory to read it. Treat the items in README "Verification" as unverified assumptions.

The README started as a copy of the DeepSeek installer's. Model-specific statements were checked against Maya's source one by one; when something looks inherited rather than verified, check it against "Maya v1.1.63 and GLM-5.3-Flash" below, not against the DeepSeek README.

## Purpose

A single-file bash installer that sets up GLM-5.3-Flash with Project Maya v1.1.63 as a service on **Ubuntu 26.04 LTS (Resolute Raccoon)**, x86_64, Server or Desktop (WSL is detected and refused). Clients are web browsers and coding agents on an intranet.

```
sudo bash install-glm-maya.sh              # interactive
sudo bash install-glm-maya.sh --quant ...  # non-interactive
sudo bash install-glm-maya.sh --uninstall
```

## Reference implementation

This is the third installer of one family, and the closest relative is `../deepseek-maya-installer-for-resolute/` (same engine project, same Maya version): `install-glm-maya.sh` was made from its `install-deepseek-maya.sh` by renaming (`DSMAYAINS_` to `GLMMAYAINS_` and so on) and rewriting only what "Where the script differs from `install-deepseek-maya.sh`" below lists. Keep the two recognisably parallel: a function with the same name does the same thing, and a fix to shared code belongs in both. Read that script's `CLAUDE.md` before changing this one; it holds what does not need repeating here and applies unless this file or the README says otherwise:

- how Maya's setup behaves (`maya.sh --setup --yes --plain --no-start --download-model`, exit code 0 after doing nothing, `api_key` in the configuration) and the checks the installer makes after it
- the nginx details that are easy to break (`Host $http_host`, a URI in every `proxy_pass`, `GET`-only key, removing the site link when `nginx -t` fails)
- `run_as` and its environment, the installer procedure in order, and the test method

`../qwen-strata-installer-for-resolute/` is the older sibling the DeepSeek installer was itself modelled on (another engine, Strata).

## Architecture (request path)

```
browser / coding agent
  → nginx (TCP 48080, selected interfaces; site glm-maya, no default_server)
    → Maya server (127.0.0.1:48081; glm-maya.service, service user)
      → maya engine (child process; GPU)
        → maya-vision (image encoder, started by the server while pictures are read)
```

destdir (default `/opt/glm-maya`) is the home directory of the service user (default `glmmaya`) and entirely owned by it. Maya's tree is `<destdir>/project-maya`, the models are in `<destdir>/models`, the installer's own files are in `/etc/glm-maya` (`install.conf`, `maya.env`, `nginx-key.conf`). Maya writes its configuration, logs, `.venv` and `~/.config/project-maya/` itself, so `maya.sh` must always run as the service user.

## Design decisions (agreed with the user on 2026-11-17; don't change without asking)

- **Maya is pinned to v1.1.63**, the version of the DeepSeek installer, although v1.1.65 was out. It is obtained as the GitHub tag archive with `curl`, not checksum-verified, and `git` must not be required. `MAYA_UPDATE_CHECK=0`.
- **CUDA toolkit, drivers, NVIDIA only, one GPU** (`--gpu PCI`): as in the DeepSeek installer.
- **Names and ports**: `glm-maya` everywhere (unit, nginx site, `/etc/glm-maya`, `/opt/glm-maya`, marker `.glm-maya-installation`), user `glmmaya`, nginx TCP 48080, Maya 127.0.0.1:48081. The family's other ports are taken: 18080 and 28080 (plamo-3-translate), 38080 and 38081 (qwen-strata), 58080 and 58081 (deepseek-maya).
- **Quantization**: Project Maya's own only: `Maya-XS`, `Maya-S24`, `Maya-S` (default), `Maya-M`, `Maya-L`. Not offered: Unsloth's GGUFs (Maya's setup cannot download them), turboderp's EXL3 quants, `Maya-M-Derisked` (in line with the DeepSeek installer leaving out EXL3 and abliterated files). The default stays `Maya-S` on every machine; where the selected GPU has 24 GB or less, the prompt says that Maya recommends `Maya-S24`. The mapping to Maya's setup id, folder and configuration name is the table in README "Quantization".
- **Context**: exactly four choices, 262144, 524288 (default), 786432, 1048576.
- **Thinking**: `--thinking none|low|high|max`, default **`max`** (the model's own default; the DeepSeek installer's is `high`). `medium`, `xhigh` and `auto` are deliberately not offered. Maya's setup writes `"reasoning_effort": "max"` on every run, so the installer sets it after each setup run. `thinking_budget` is left alone.
- **Drafting**: `--drafting skip|measure|on`, default `skip`. `skip` = Maya's `--draft mtp` (no drafter; on one GPU no drafting at all); `measure` = `--draft dflash2 --drafting measure`; `on` = `--draft dflash2 --drafting on`. **DFlash2 is CC BY-NC-ND 4.0 (non-commercial)**: never a default, and the license is shown in the question and in the summary; there is no separate confirmation. `measure` and `on` stop the installer with `--parallel` above 1 and on a GPU below compute capability 8.0. A `measure` whose measurement Maya did not make (see the facts below) stops the installer after Maya's setup; it does not fall back to `on` or `skip` by itself.
- **Pictures**: `--vision` (default) / `--no-vision`. With `--vision` the installer also installs `ffmpeg` from apt (video input). Because Maya's setup only warns when the image encoder does not build, the installer checks for it afterwards and stops.
- **Tuning**: `--calibrate`, never asked, default off, **not saved in `install.conf`**. The intended use is: install, check that the service works, re-run with `--calibrate` if wanted. A tuning Maya did not make is a warning, not an error.
- **Options**: asked: `--destdir --user --quant --gpu --ctx-size --thinking --drafting --web-port --interfaces --web-api-key --agent-api-key --open-ports`; never asked: `--parallel` (default 1), `--vision`/`--no-vision` (default on), `--calibrate`/`--no-calibrate` (default off), `--maya-port`. There is **no license confirmation** (model and quantizations are MIT).
- **Conversations kept**: `MAYA_GLM_SLOT_KEEP=1` through the setup's `--env`.
- **Maya's refusal ablation stays available** (decided 2026-11-17): Maya's setup downloads a "refusal direction" for GLM-5.3-Flash into `models/refusal-directions/` and starts the engine with `--ablate FILE --ablate-default off`; any request can ask for `"ablate": true`, and the web chat has a switch per chat. The installer must not take `ablate` or the `--ablate` arguments out of the configuration, and adds no option for it. The user's reason: a model of this size sometimes refuses harmless requests by mistake, and users need a way around that. It stays off by default, and README "Engine" and "Known limitations" say what it is.
- **API key, nginx, model management off, uninstall, TLS out of scope**: as in the DeepSeek installer (its `CLAUDE.md`, "Design decisions"), with `glm-maya` names. Management requests never get the key added.
- **Coexistence**: `Conflicts=deepseek-maya.service qwen-strata.service` in the unit; the installer stops and disables each of the two when it is running, starting, waiting for a restart or enabled, before Maya's setup, and the summary announces it; `--uninstall` only prints how to enable them again. With plamo-3-translate: `After=plamo-3-translate-llama.service plamo-3-translate-uwsgi.service`, and plamo's side must not name our unit. Other installers' units are only named in `[Unit]` and stopped or disabled; never edit or remove their files. **The other two installers are not changed from this repository**: what they need is passed on in hand-over notes (`<repository name>.md` in the working directory, in Japanese, untracked and listed in `.git/info/exclude`; they must stay out of the repository). Both know `glm-maya.service` since 2026-11-17 (qwen-strata: commit `b347c2b`; deepseek-maya: commit `9dd4b3a`): each has the same `..._EXCLUSIVE_UNITS` list with the other two units and the same three functions, so the three are symmetric, and the README says so under "Coexistence with other services", with a note on older copies of those installers. Their READMEs rely on our unit naming theirs in `Conflicts=`: tell them (a note) before changing that.

## Open points for later

- **`clear_thinking`**: Z.ai recommends `clear_thinking=true` for chat; Maya's default is the model's (`false`). Not set by the installer. How much of a web chat's prompt is read again per turn is to be measured on real hardware.
- **`systemd-oomd`**: Maya's setup warns about it on machines with 128 GB of RAM or more. Whether it can end a system service that loads this much is listed in README "Verification".

## Maya v1.1.63 and GLM-5.3-Flash: what its source says

Read on 2026-11-17 from the tag archive (`docs/MODELS.md`, `docs/MEMORY.md`, `docs/SETUP.md`, `docs/SETTINGS.md`, `docs/GLM53.md`, `maya.py`, `tools/maya_quants.py`, `serve/frontend.py`, parts of `serve/server.py`); nothing was run. These are facts about Maya, not decisions about the installer. v1.1.65 was the latest release that day (v1.1.64 and v1.1.65 change AMD pairings and error reporting, nothing the installer uses).

- **Two different models share the engine `build/maya`**: GLM-5.3-Flash (321 B, family `glm`, served as `glm-5.3-flash`) and GLM-5.3 (744 B, "glm-dsa", text only, its own defaults). `docs/GLM53.md` and every `G53_*` / `glm_dsa_*` name are about the latter. Do not mix their figures.
- **Downloads Maya's setup knows** (`MODELS` in `maya.py`; setup id for `--model`, key used for folders and configs, download size, whole model in VRAM + RAM):
  `glm-maya-s` = `Maya-S-v2-IQ2_XXS` 96.5 GB / ~104 GB (default); `glm-maya-s24` = `Maya-S24` 94.7 / ~102 (recommended by Maya when every card has 24 GB or less); `glm-maya-xs` = `Maya-XS-IQ1_S` 73.4 / ~80 (written with `--kv int8`, thinking budget 8192, sampling of its own; Maya recommends 128K for it); `glm-maya-m` = `Maya-M` 116 / ~124; `glm-maya-m-derisked` = `Maya-M-Derisked` 116 / ~124 (a weight edit that reduces refusals, another repository, experimental); `glm-maya-l` = `Maya-L` 156.3 / ~164; turboderp's `EXL3-3.05bpw` 125.3 and `EXL3-4.05bpw` 165.2 (`EXL3-sc_4.10bpw` by hand only). Every file has a pinned SHA-256; most repositories are read at `main`. `--model` takes one name (`maya.py`, `model_option`); there is no counterpart of `--ds4-quant`.
- **Unsloth's GGUFs of GLM-5.3-Flash are not among them.** They run only as files the user already has (`--gguf-dir DIR`), which Maya calls experimental and does not measure; nothing is pinned or verified for them.
- **Files**: model folder `<models>/<key>/` (e.g. `models/Maya-S-v2-IQ2_XXS/`), pack `<model folder>/pack/` (`PACK_FILES`: `index.txt`, `native_experts.txt`, `dense.bin`, `tokenizer/...`), kept conversations `<pack>/slots` (`MAYA_GLM_SLOT_DIR`, 16 GB cap), pictures `<model folder>/vision/`, drafter `<models>/GLM-5.3-Flash-DFlash2/`, `<models>/refusal-directions/`. The configuration is **`maya-<key in lower case>.json`** (`glm_config_path`; e.g. `maya-maya-s-v2-iq2_xxs.json`), the engine log the same name with `.log`, the start script `run-maya-<key>.sh`: there is no `maya-glm.json`, and a change of quantization leaves the old configuration beside the new one. The installer record is `installer.quant` (the key), not `ds4_quant`.
- **What the setup writes** (`write_config`): `args` = `--glm-pack <pack> --max-context N --expert-cache auto --prefill auto --kv-streaming on` (+ `--kv int8` for Maya-XS, `--dflash FILE`, `--parallel N`, `--expert-profile`, `--ablate`), `reasoning_effort` = **`max`** on every run, `sampling` temperature 1.0 / top-p 0.95, `vision`, `env`, `log`, `port`. On a re-run it keeps `host`, `api_key`, `cors_origins`, `mcp_servers`, `thinking_budget` and some `args` (`--expert-cache`, `--vram-reserve-mib`, `--prefill`, `--parallel`, `--kv-streaming`, `--kv-resident`) from the configuration before, but not `--dflash`.
- **Context**: the setup offers 8K, 32K (default), 64K and 128K, but `--context N` is passed through unchecked (`choose_context`), and the documentation reports 256K, 512K and 1M in use. The model's own maximum is 1,048,576. With KV streaming (on in every configuration) each attention layer's cache lives in pinned RAM and only a window of 32768 positions in VRAM, so a long context costs **RAM, not GPU memory**: about 6 KB a token with the INT8 cache (the default since v1.1.55: 544 bytes a token in each of the 11 attention layers; `docs/MEMORY.md` says about 0.2 GB at 32K; a comment in `maya.py` still says 12 KB, the FP16 figure), i.e. roughly 1.6 / 3.2 / 4.8 / 6.4 GB at 256K / 512K / 768K / 1M for each conversation. These figures are derived, not measured.
- **Thinking**: GLM's own levels are Low, High and Max, and Max is the model's default (Z.ai's card; Maya's default since 2026-10-27, though Maya's README still says High). Maya's `reasoning_effort` takes `none`, `auto` (= the model's default, Max), `low`, `medium` (= High), `high`, `xhigh` (= Max), `max`; a number stops the start. Off is Maya's own doing (the server closes the thinking block), while Z.ai's API says thinking cannot be disabled.
- **Pictures and video**: GLM-5.3-Flash is a vision model. Unless `--no-vision` is given, the setup compiles a second program (`build-vision/bin/maya-vision`, 10 to 20 minutes; `cmake` and `ninja` from `.venv`, no extra apt packages) and downloads 1.14 GB; if that build fails the setup only warns and the configuration has no `vision` entry. Video input needs `ffmpeg` and `ffprobe` on the host; `poppler-utils` improves PDF reading.
- **Drafting**: the model's own MTP block (default; it drafts on two GPUs or more, **one GPU decodes without drafting**), or the DFlash2 drafter (`--draft dflash2`, 0.7 GB, offered by Maya on NVIDIA sm_80 or newer only, one request at a time, **CC BY-NC-ND 4.0, non-commercial**). `--drafting measure|on|off` only matters with DFlash2 (`measure` runs the speed calibration during the setup, also with `--no-start`; `--yes` without `--drafting` measures). There is no DSpark for GLM.
- **Tuning**: `--calibrate` with `--setup` runs `calibrate_config` after the configuration is written (10 to 15 minutes, needs the GPU free, never fails the setup). The result goes into the configuration's `env` (`MAYA_GLM_PCIE_SHARE`, `MAYA_GLM_CPU_LANE`, `MAYA_GLM_READ_CHUNKS`) and into `~/.config/project-maya/calibration.json` of the service user, from where later setups apply it for the same hardware and model. A setup with `--yes` or `--no-start` is not offered the tuning by itself.
- **Conversations**: GLM keeps four conversations aside on the SSD by default (`MAYA_GLM_SLOTS=4`) and checkpoints in RAM (`MAYA_GLM_CKPTS=4`); `MAYA_GLM_SLOT_KEEP=1` only makes the slots survive a restart of the engine (unused ones are removed after `MAYA_GLM_SLOT_DAYS`, 7). This is more than DeepSeek's engine does without its switch. There is no GLM counterpart of `MAYA_DS4_KEEP_THINKING`.
- **Requirements**: compute capability 6.0 for the engine (7.5 with CUDA 13), driver 580 with CUDA 13, Blackwell needs CUDA 12.8 or newer. AVX2 is not required by Maya (a warning); the installer requires it, as its siblings do.
- **Unattended starts** never run a calibration (`unattended_start`: `--yes`, `INVOCATION_ID` or `NOTIFY_SOCKET` in the environment, or standard input not a terminal).
- **The `installer` block is written anew by every setup** (`write_config`: `cfg["installer"] = {...}`; only `thinking_budget_set` is taken from the configuration before), so a `speed_calibration` found after a setup run was written in that run. Checked on 2026-11-17 after the DeepSeek side asked; `write_config_ds4` does the same.
- **Measurements that silently do nothing** (`maya.py`: `speed_calibration`, `calibrate_config`, `busy_gpus`): both need the GPU to themselves. With more than 1024 MiB of the configuration's GPU in use (`nvidia-smi`, `memory.used`) they print a warning and return, and the setup still exits 0; an exception inside them is caught the same way. What tells the cases apart is the configuration: a measured drafter has `installer.speed_calibration.kept` (`dflash2` or `mtp`; with `mtp` the `--dflash` argument is gone), a broken-off one has `installer.speed_calibration.failed`, a skipped one has no `speed_calibration` at all, and `--drafting on` records `"skipped": "chosen"`. `installer.draft` is written before the measurement and proves nothing. After a skipped or failed measurement the configuration still drafts with DFlash2. A tuning that ran writes `~/.config/project-maya/calibration.json`.
- **A tuning result is keyed** (`hardware_key`) by the GPU's name and memory, the CPU, the RAM, the quantization, the context, pictures or text, and whether `--dflash` is in the arguments; `write_config` applies a saved one for the same key (or, for another context only, the nearest). The configuration's `env` from the run before is not kept otherwise.
- **`--draft` given on the command line is taken as it is** (`choose_draft`): Maya's own rule against DFlash2 below sm_80 is only applied when it chooses itself.
- **The pack** is `<model folder>/pack`, or `pack-<name>` when `pack/` indexes other files of that folder (`pack_step`); the configuration's `--glm-pack` argument is the place to read it from.
- **`Maya-S24` is recommended** by the setup when every GPU in use has `vram_gb <= 24.5`.
- **Files beside a configuration** (`serve/models.py`, `serve/server.py`): `maya-<name>.json.prev` (the settings before a change made through the page) and `maya-<name>.shared-settings.json` (the "shared" Chat settings a key holder saves with `POST /settings`: thinking level, max tokens, sampling). The shared thinking level fills in every request that names none, before the configuration's `reasoning_effort`; `GET /settings` (key needed) returns it as `defaults`, while `/health` `defaults.reasoning_effort` is always the configuration's. The same holds for DeepSeek's `maya-ds4.json`.
- The server (`serve/server.py`) is the same program for every model: the paths, the API key rules and `MAYA_API_KEY`, `MAYA_MODEL_MANAGEMENT`, `MAYA_UPDATE_CHECK` are as the DeepSeek installer uses them.

## Code conventions

- Every shell variable of the installer — globals, arrays and `local`s — is prefixed with `GLMMAYAINS_`. User-facing environment variables are prefixed with `GLMMAYA_`. Exceptions: bash builtins, `DEBIAN_FRONTEND`, the variables Maya itself reads (`MAYA_*`), and the key names inside `install.conf` and associative arrays. Do not source external files into the installer's shell (`install.conf` and `os-release` are parsed).
- The file must not execute when sourced (`main` runs only if `BASH_SOURCE[0] == $0`), so that functions can be exercised from a test script as a normal user.
- Yes/no questions ask again on invalid input; other invalid answers stop the installer in validation.

## Where the script differs from `install-deepseek-maya.sh`

Everything not listed here (GPU and interface selection, ufw, the nginx site, the key files, `run_as`, `wait_port_free`, `start_services`, `save_config`) is the DeepSeek script with the names changed. The differences, which are also the things that are easy to break:

- **Constants**: `GLMMAYAINS_MODEL` is only shown; Maya's `--model` takes the setup id and the folders are named after Maya's key, both from `GLMMAYAINS_QUANT` ("setup id, key, download in units of 100 MB, memory in GB"; `quant_download` prints the GB). `maya_name`, `maya_config` and `maya_log` give the names that depend on the quantization (`maya-<key in lower case>`); nothing else may spell them out.
- **`--calibrate`** is `GLMMAYAINS_CALIBRATE`, handled like `GLMMAYAINS_OPEN_PORTS`: not in `GLMMAYAINS_KEYS`, so never written to or read from `install.conf`.
- **`validate`** stops `measure` and `on` with `--parallel` above 1; **`preflight`** stops them below compute capability 8.0. Maya checks neither when `--draft` is given, nor `--context`: these are the only checks.
- **`preflight`, memory**: RAM + GPU memory against the whole-model figure plus `GLMMAYAINS_CTX_BYTES` (6144) x context x `--parallel`. A warning only.
- **`unit_in_use`, `exclusive_units_in_use`, `disable_exclusive_units`** loop over `GLMMAYAINS_EXCLUSIVE_UNITS`; the summary and `--uninstall` use the same list.
- **`gpu_busy_check`** runs after the services are stopped and before Maya's setup, and only with `measure` or `--calibrate`: more than 1024 MiB in use on the selected GPU is a `warn_continue`.
- **`install_maya`** carries over, into the tree of a new version, only the selected quantization's `maya-<name>.json` and `.shared-settings.json`.
- **`setup_maya`**: `--model <setup id>`, `--draft mtp` for `skip` (never leave `--draft` out: with `--yes` Maya would take the answer of the setup before), `--draft dflash2 --drafting measure|on`, `--calibrate`, `--env MAYA_GLM_SLOT_KEEP=1`; `ulimit -l unlimited` in the subshell around `run_as`, because the engine loads of `measure` and `--calibrate` happen outside the unit. The checks afterwards, in order: the configuration written in this run (mtime), `installer.quant` equal to Maya's key, `build/maya` executable, `index.txt` in the pack the configuration names (`config_arg FILE --glm-pack`, never a fixed path), with `--vision` an executable `vision.exe`, with `measure` `installer.speed_calibration.kept` present and no `failed` (else `die`), with `--calibrate` a `calibration.json` written in this run (else `warn`).
- **`set_thinking`** writes one of the four words and still removes `api_key`. It must leave `ablate` and the `--ablate` arguments alone.
- **`remove_other_configs`** (after `set_thinking`) removes, for the four other quantizations, `maya-<name>.json`, `.json.prev`, `.shared-settings.json` and `run-maya-<name>.sh`, each by name and as the service user; no glob (a `maya-*.json` of the user's own stays), and the logs stay.
- **`write_unit`, `write_logrotate`, `wait_health`, `finish`** take the configuration and the log from `maya_config` / `maya_log`. The logrotate rule names the one log: `maya-*.log` would match `maya-setup.log`.
- **`smoke_test`** calls `check_thinking`: warnings only, when `/health` reports another level than `--thinking` (`effort_level` maps Maya's other spellings), when `GET /settings` returns a saved level that differs, or when `GET /settings` cannot be read (as in the DeepSeek script, which compares only the saved level: it does not compare `/health`, and its `thinking_word` knows two pairs only). **`finish`** says whether the configuration has `--dflash`.
- **`cleanup_old_models`** offers only `models/<key of another offered quantization>/`; `GLM-5.3-Flash-DFlash2/`, `refusal-directions/` and anything else are never offered. Each quantization's `vision/` is inside its own folder (1.14 GB is downloaded again for another quantization).
- **apt**: `ffmpeg` in addition, only with `--vision`.

## Testing

There is no test suite. The file is not executed when sourced, so functions can be exercised from a test script as a normal user. All of the following was done for the first implementation (2026-11-17; results in README "Verification"); the scripts lived in a scratch directory and are gone, so recreate them when the code they cover changes. The method is that of "Testing" in `../deepseek-maya-installer-for-resolute/CLAUDE.md`:

- `bash -n install-glm-maya.sh`; `shellcheck install-glm-maya.sh` (0.11 is installed on the development machine; keep it free of findings).
- A driver script that sources a copy of the installer made with `sed 's#="/etc/#="<scratch>/etc/#'` (the paths under `/etc` are `readonly`), overrides `net_interfaces`, `ufw_active`, `service_exists`, `systemctl` (logging its calls), `chown`, `port_free`, `mktemp`, `curl` (copies a stand-in archive when called with `--output`) and `run_as` (the same `env -i`, without `runuser`), runs `parse_args` → `load_saved_config` → `resolve_values` → `require_gpu` → `prompt_values` → `validate` → `prompt_gpus` → `prompt_interfaces` → `prompt_ufw` and then the functions named on its command line. One process per case. `/proc/meminfo` is replaced by overriding `awk`, the free disk space by overriding `df`.
- A stand-in `nvidia-smi` in `PATH` that answers the four `--query-gpu=` forms used (`index,pci.bus_id`; `pci.bus_id,memory.total,memory.used,name`; `pci.bus_id,compute_cap`; `driver_version`) from a table.
- A stand-in release archive whose `maya.sh` records its arguments, environment and standard input and writes what Maya's setup writes (the configuration with `installer.quant`, `--glm-pack`, `--dflash`, `--ablate`, `vision`, `speed_calibration`; `build/maya`; the pack; `run-maya-<name>.sh`; `calibration.json`), with a mode for each failure listed in README "Verification". It must be updated when the facts above are found to be wrong.
- The questions were looked at once through `script -qec` (a pseudo-terminal): `read -p` prints no prompt when standard input is a pipe.
- nginx: print `nginx_site`, run a private nginx (`nginx -c <conf> -p <dir>` with `pid` and temp paths in the scratch directory) in front of a small Python server that enforces the key like Maya (exempt `GET /`, `/web/`, `/fonts/`, `/health`; `Authorization: Bearer` or `x-api-key`; 403 for a `POST` whose `Origin` is not the `Host`), echoes the path and headers it received in response headers, and answers `/health`, `/settings` and `/v1/models`; a Python client sends raw paths (`http.client`, no normalization). Requests that end in `location /` reach Maya with the path as the client wrote it; what matters there is that no key is added. Repeat it after any change to the site.
- The whole of `do_install` with `install_packages` and `ensure_user` overridden, `systemctl restart glm-maya.service` starting that server and `systemctl reload nginx.service` reloading the private nginx; the log of `systemctl` and `run_as` calls gives the order of the steps.
- What needs root or a GPU cannot be tested on the development machine and is listed in README "Verification" for the first run on real hardware (planned machine: Ryzen Threadripper PRO 3995WX, 512 GB DDR4-3200, GeForce RTX 5080 Ti 12 GB). If an assumption turns out wrong there, the installer most likely stops in `install_packages`, `setup_maya` or `smoke_test`; fix the installer and the README, not the symptom.
